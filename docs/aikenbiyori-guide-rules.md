# 愛犬日和 Webヘルプ（Guideページ）情報設計ルール

このドキュメントは `/aikenbiyori/` 配下に「はじめての方・基本操作」「今日のケア」「AIに相談」「記録・愛犬プロフィール」「プラン・課金・広告」「データ・バックアップ」「トラブルシューティング」などのヘルプページを追加していく際に、どのAIエージェント（Codex / Claude Code など）が作業しても同じ方向性で実装できるようにするためのルールです。

対象は **Webサイト側のみ**（`/aikenbiyori/` 配下のNext.jsページ）です。愛犬日和Flutterアプリ本体には一切関係しません。

---

## 1. ヘルプページの目的

- 愛犬日和を使い始めたユーザーが、迷わず機能を使えるようにする。
- 開発者向けのマニュアルではなく、**飼い主さん向けの案内**であることを常に意識する。
- 長文マニュアル化させない。1ページ・1セクションを短く保つ。

---

## 2. 文体

- 基本は「です・ます」調。
- 企業マニュアルのようなフォーマルすぎる表現は避ける。
  - 避ける例: 「必要事項をご入力いただき、保存ボタンを押下してください。」
  - 望ましい例: 「名前や誕生日などを入力したら、『保存』をタップします。」
- 短く・やさしく・正確に。不要な説明を増やさない。
- 技術用語（API、DB、キャッシュなど）を利用者へ見せない。
- 可愛くしすぎない・馴れ馴れしくしない。絵文字は基本的に使わない。

---

## 3. デザイン

- 愛犬日和トップページと同じ世界観（やさしい・温かい・清潔感・柔らかい）を維持しつつ、ヘルプページでは装飾を減らす。
  - 目安: トップページ＝世界観60/情報40、ヘルプページ＝世界観30/情報70。
- **新しいデザイントークンを増やさない。** `src/app/aikenbiyori/aikenbiyori.css` の `.aiken-site-shell` に定義済みのCSSカスタムプロパティ（`--aiken-bg` `--aiken-surface` `--aiken-text` `--aiken-muted` `--aiken-olive*` `--aiken-orange*` `--aiken-border` `--aiken-shadow`）をそのまま使う。
  - `globals.css` の `.faq-page` は `--aiken-accent*` という重複した別名トークンを再定義してしまっている過去の実装だが、これは踏襲しない（今後修正候補ではあるが、今回のFAQページ自体は変更していない）。
- 新規スタイルは `src/app/aikenbiyori/aikenbiyori.css`（`.aiken-site-shell` にスコープされたファイル）に追記する。`globals.css` には置かない。
- 新規クラス名は `aiken-guide-*` プレフィックスで統一する。
- border-radius・breakpoint（560px / 900px / 720px / 360px）・コンテナ幅（`min(100% - 2rem, ...)`）は既存の値を踏襲する。

---

## 4. 基本構造

各Guideページは原則として以下の順で構成する。

1. パンくず（`Breadcrumb`）
2. ページタイトル＋短い導入（`GuideHero`）
3. 必要なら目次（`TableOfContents`）
4. 各説明セクション（`GuideSection`。見出し＋短い説明＋スクリーンショットまたは動画＋必要な場合のみ補足・注意）
5. 関連する使い方（`RelatedGuides`）
6. よくある質問／解決しない場合の導線（`HelpFooter`）

共通コンポーネントは `src/components/aikenbiyori/guide/` にある。すべてpropsで内容を受け取る設計で、FAQのようなJSON駆動にはしていない（ページごとの内容差が大きいため）。

| コンポーネント | 役割 |
| --- | --- |
| `Breadcrumb` | パンくずリスト |
| `GuideHero` | ページ見出し＋導入文 |
| `TableOfContents` | ページ内目次（0件の場合は自動的に非表示） |
| `GuideSection` | 見出し＋説明＋メディア＋補足のセクション単位。`layout="split"` で900px以上のとき2カラム表示 |
| `GuideMedia` | スクリーンショット／動画の共通表示枠（詳細は5・6章） |
| `GuideNote` | 補足・注意書き（`variant="note"` = オリーブ系、`variant="warning"` = オレンジ系） |
| `RelatedGuides` | 関連ガイドへの導線カード一覧。`status: "planned"` は非リンクの「準備中」表示になる |
| `HelpFooter` | FAQへの導線＋メール問い合わせ導線 |

新しいレイアウトパターンが必要になった場合も、まず既存コンポーネントの組み合わせで表現できないか検討し、明らかに複数ページで再利用するものだけ新規コンポーネント化する。

## 5. スクリーンショットの扱い

- `GuideMedia`（`kind="image"`）を使用する。
- `next/image` の `fill` + `sizes` を使う（`FeatureSection` と同じ流儀）。`images.unoptimized: true` のため最適化はされないが、レスポンシブなレイアウトのために `fill` を使う。
- `alt` は必須。内容が分かる具体的な説明を書く（例:「今日のケア画面で散歩時間を確認しているスクリーンショット」）。
- `caption` は任意。
- 素材（`src`）が未設定の場合は自動的にプレースホルダー枠が表示される。**「SCREENSHOT TODO」のような文言は開発時（`NODE_ENV !== "production"`）のみ表示され、本番ビルドでは文言が出ない。** 本番に出したくない一時テキストは、この仕組みの外に直接書かないこと。
- 端末モックに過剰にはめ込まず、内容が見やすいことを優先する。

### 5.1 表示サイズ（`size="standard"` / `size="compact"`）

縦長の実アプリスクリーンショット（`aspect-ratio: 1320 / 2868` は変更しない）は、スマホ表示で幅いっぱいに広がると画像が文脈を支配してしまう。そのため `GuideMedia` の `size` props で以下を使い分ける。**新しいGuideを作るたびに人間へサイズ判断を求めず、この基準をAIエージェント自身の既定判断として使う。特殊な画像だけ例外として個別検討する。**

| | スマホ幅の目安 | 用途 |
| --- | --- | --- |
| `standard`（既定） | 親幅の86%・max-width 340px・中央寄せ | 詳細Guideで通常使う実アプリ画面。今日のケア詳細、AI相談画面、設定画面、更新ダイアログなど、UIの内容も確認してほしい画像 |
| `compact` | 親幅の78%・max-width 320px・中央寄せ | Getting Startedのような概要・導入Guide。画面の細部よりも「こういう画面です」と見せる用途、複数機能を順番に紹介するページ |

- PC（900px以上、`layout="split"` の2カラム表示）では `standard` `compact` とも幅制限を解除し、既存の分割カラムに自然に収まる状態を維持する。PC側まで縮小しない。
- どちらのサイズも `.aiken-guide-media-frame` の `aspect-ratio` はそのまま（トリミングや上下欠けを発生させない）。

---

## 6. 動画の扱い

- `GuideMedia`（`kind="video"`）を使用する。
- 数秒程度の短い操作動画を想定。MP4 / WebM。
- `muted` `playsInline` `loop` は常に付与される（コンポーネント側で固定）。
- `autoplay` は既定で無効。有効にする場合は通信量とアクセシビリティを考慮したうえで明示的に指定する。
- GIFは使用しない。
- `sources` が未設定の場合はスクリーンショットと同様にプレースホルダー表示になる（本番では文言なし）。

---

## 7. モバイルファースト

- スマートフォンでは常に1カラム。
- PCでは `GuideSection` の `layout="split"` を使うと900px以上で「文章＋メディア」の2カラムになる。
- 目次・関連ガイド一覧も900px以上でグリッド段数が増える（既存CSSで対応済み）。
- 新しいブレークポイントを追加しない。560px / 640px / 900px / 720px / 360px の既存値を使う。

---

## 8. AI・医療表現に関する注意

愛犬日和は生成AIを使用しているが、Webヘルプでは以下を守る。

- 「AIが正しい判断をする」「AIが診断する」といった表現は使わない。
- 基本的な位置付けは「愛犬の情報や天気などをもとに、判断材料を整理する」こと。
- 診断・治療・獣医師の代替ではないことを、AI関連の機能を説明するセクションでは必ず注意書き（`GuideNote variant="warning"`）として添える。
- 文例（既存の `FeatureSection` の note・`/aikenbiyori/guide/` サンプルセクションで使用済み）:
  「愛犬日和は診断や治療を行うアプリではありません。緊急時や症状が気になる場合は、動物病院へ相談してください。」

---

## 9. 最新アプリ仕様との照合が必要な項目

このドキュメントおよびGuideページの文章は、Webサイト側の実装時点の理解に基づく。実際のFlutterアプリの挙動・画面構成・機能名は変更されている可能性があるため、個別ページ（今日のケア・AIに相談・記録など）を作成する際は、**着手前に必ずアプリ本体の最新仕様を確認**すること。特に以下は差異が出やすい。

- 機能名・メニュー名（トップページの「今日のケア」「AIに相談」「記録」という名称が変わっていないか）
- AI相談の実際の入力・出力フロー
- プラン・課金・広告の内容（無料/有料の範囲、広告表示条件）
- データ・バックアップの実際の操作手順（エクスポート/インポートの有無など）

このリポジトリはWebサイト専用であり、アプリ本体のコードは含まれない。仕様確認は別途アプリ側の担当者・リポジトリで行う。
